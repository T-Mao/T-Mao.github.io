ThreeTodo App

An iOS task manager organized around Plan, Today, and Thoughts.

Three places for a task to belong

I built ThreeTodo in April 2024 as a SwiftUI task manager with three lists: Plan, Today, and Thoughts. The idea was to give a task or an unfinished idea a place immediately, without requiring a due date, priority, or project structure first.

I developed the app independently, focusing on inline editing, movement between lists, and a small set of reusable interactions.

Move the task, rather than reopen a form

Each list is a page in a swipeable TabView. Tasks can be reordered within a list or moved to another category through drag and drop. A task is removed from its original list before being added to the destination so the same item does not remain in two places accidentally.

I also added a trash drop zone and contextual actions. These made movement and deletion part of the same interaction language as reordering.

Editing without a separate screen

Task text is editable in place. Longer text expands the editor rather than disappearing into a fixed-height field. I used NSLayoutManager and NSTextContainer from UIKit’s text layout system to estimate the height needed for the available width.

This was a useful exercise in combining SwiftUI’s layout with a lower-level text system. The measurement needed to agree with what the user actually saw, especially as text changed.

Structure when you need it

Divider items let people group a list into sections such as morning, afternoon, and evening. Reusable divider templates make that structure easy to insert again, while keeping ordinary tasks simple.

The app keeps the three task arrays in shared state and persists them with Codable JSON in UserDefaults. For this small local app, that made the relationship between the visible lists and saved data straightforward to inspect.

What I learned

ThreeTodo was an exercise in restraint. The most demanding parts were not the number of features, but the transitions between them: editing while the list resizes, dragging while navigation is available, and moving an item without duplicating it.

It helped me become more deliberate about interaction details and about choosing a scope I could implement and test independently.
