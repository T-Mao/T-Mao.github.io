SparkDays App

A habit tracker that turns check-ins into self-chosen rewards.

Give a habit a reward that matters to you

SparkDays connects a daily habit with a personal reward system. Users define tasks, check in as they complete them, and earn virtual coins that can be exchanged for rewards in a customizable store. A reward might be a small treat or an experience the user wants to set aside time for.

I built the app independently, handling the concept, design, Swift and SwiftUI implementation, data model, testing, and App Store release.

Make progress visible

Each task has a target number of days and a grid showing completion. Difficulty settings determine the base coin amount, while streak milestones can add a bonus. The store groups rewards by scale and lets users edit their own items.

The coins are an organizing device for the user’s own goals. The point is to make the relationship between effort and reward visible, without prescribing what someone should find motivating.

The state needs to agree

A check-in affects several parts of the app: the completed-day count, the task’s history, the coin balance, and possibly a streak bonus. I used a shared AppViewModel to coordinate tasks and store items, keeping these changes out of individual display components.

Tasks record their completion dates so a repeat check-in on the same day does not award the same daily coins again. Buying a store item checks the available balance, subtracts its price, records its purchased state and date, and moves it to the owned view.

That logic is the center of the app. A progress bar and a reward balance are useful only if they describe the same underlying history.

SwiftUI and persistence

Task and shop-item models expose changes to SwiftUI through observable state. I convert the saved data to Codable representations and store it as JSON in UserDefaults. Reusable task and item cards, sheets, and context menus provide the main editing interactions.

Haptics and a brief coin-change message give immediate feedback after an action. I wanted a check-in to feel acknowledged while leaving the user on the task they came to complete.

What I learned

SparkDays gave me practice building a small economy with consistent rules. The visible feature is playful, but the implementation needs ordinary discipline: prevent duplicate rewards, keep purchases consistent, and restore the same state after relaunching.

The project also helped me separate a design intention from a demonstrated result. The app is designed to make habit tracking more rewarding; whether a particular reward helps someone maintain a habit is personal.
